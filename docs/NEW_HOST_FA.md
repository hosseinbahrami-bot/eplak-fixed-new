# انتقال به هاست تازه — راهنمای گام‌به‌گام (ای‌پلاک)

این راهنما برای وقتی است که هاست عوض شده (یا دامنه/پوشه تغییر کرده) و سایت یا اپ
خطا می‌دهد — رایج‌ترین نشانه: **«ارسال کد تایید انجام نشد»** هنگام ورود با شماره موبایل.

---

## ۰) چرا بعد از جابه‌جایی هاست این خطا می‌آید؟

| # | علت | چرا روی هاست قبلی کار می‌کرد |
|---|---|---|
| ۱ | فایل **`shared/config.php`** روی هاست تازه وجود ندارد | این فایل عمداً **در گیت و در بسته‌ی آپلود نیست** (رمز دیتابیس و کلید پنل پیامک داخلش است). روی هاست قبلی یک‌بار دستی ساخته شده بود و با عوض شدن هاست، از بین رفت |
| ۲ | نام کاربری/رمز/نام دیتابیس هاست قبلی روی هاست تازه وجود ندارد | پیش‌فرضِ کد `wigitali_root` / `wigitali_eplak-db` است که روی نصب تازه ساخته نشده |
| ۳ | کلیدهای **پنل پیامک** (Payamak یا AmootSMS) هم داخل همان `config.php` بودند | بدون آن‌ها API پاسخ می‌دهد: «ارسال پیامک فعلاً پیکربندی نشده است.» |
| ۴ | دامنه یا پوشه‌ی سایت عوض شده، ولی اپ موبایل آدرس قدیمی را دارد | `core/storage.js` برای اپ (پروتکل `file://`) آدرس `https://eplak.ir/eplak-fixed/api` را نگه می‌دارد |

نکته‌ی مهم درباره‌ی پیامِ خطا: پیش از این، وقتی دیتابیس در دسترس نبود، API یک
**صفحه‌ی HTML خطا** برمی‌گرداند؛ اپ نمی‌توانست JSON بخواند و فقط پیامِ کلی
«ارسال کد تایید انجام نشد» نشان می‌داد. حالا اندپوینت‌های `api/` همیشه JSON
برمی‌گردانند و **دلیلِ واقعی** (مثلاً «shared/config.php وجود ندارد — setup.php
را باز کنید») در همان پیام دیده می‌شود؛ یعنی حتی اپِ نصب‌شده‌ی قدیمی هم دلیل را
نشان می‌دهد و نیازی به نصب نسخه‌ی تازه نیست.

---

## ۱) تشخیص در ۳۰ ثانیه

یکی از این دو نشانی را در مرورگر باز کنید (به‌جای `YOUR-SITE`، دامنه/پوشه‌ی خودتان):

```
https://YOUR-SITE/api/status.php
https://YOUR-SITE/setup.php
```

خروجی `api/status.php` یک JSON است با این کلیدها (هیچ رمزی چاپ نمی‌شود):

| کلید | یعنی |
|---|---|
| `otp_ready` | **«ارسال کد تایید» کار می‌کند؟** (یک نگاه: `true` یعنی مشکل حل است) |
| `problems` | فهرستِ مشکل‌ها **با راه‌حلِ هرکدام** به فارسی |
| `config_exists` | آیا `shared/config.php` هست؟ (مهم‌ترین مورد) |
| `db.ok` / `db.error` / `db.tables` | رسیدن به دیتابیس، خطای واقعی، و ساختِ جدول‌های اصلی (`users`, `reports`, `notifications`, `news`, `device_tokens`, `otp_challenges`, `admin_users`) |
| `sms.ready` / `sms.provider` | آیا پنل پیامک (Payamak/AmootSMS) تنظیم شده؟ |
| `extensions.pdo_mysql` / `extensions.curl` | آیا اکستنشن‌های لازم در PHP فعال‌اند؟ |
| `writable.*` | نوشتنی بودن `shared/`, `uploads/`, `data/` |
| `setup_url` | نشانیِ صفحه‌ی راه‌انداز |

> `api/ping.php` عمداً دست‌نخورده مانده: آن اندپوینت **هرگز** دیتابیس را لمس
> نمی‌کند تا پرده‌ی «بدون اینترنت» اپ حتی وقتی دیتابیس خراب است درست کار کند.

`setup.php` همان اطلاعات را به‌صورت جدولِ خوانا + فرمِ ساختِ تنظیمات نشان می‌دهد.

---

## ۲) آپلود فایل‌ها

بسته‌ی `eplak-fixed-update.zip` را در پوشه‌ی سایت باز کنید (Extract):

1. cPanel ← **File Manager** ← پوشه‌ی `public_html/eplak-fixed` (یا هر مسیری که سایت آنجاست).
2. اگر نسخه‌ی قبلی هست، **پشتیبان** بگیرید (روی پوشه ← `Compress`).
3. بسته را آپلود و Extract کنید.
4. این‌ها را **پاک نکنید**: `shared/config.php` (اگر هست)، `uploads/`، `data/`.

> اگر هاست تازه کاملاً خالی است، `shared/config.php` وجود ندارد ⇒ مرحله‌ی بعد.

---

## ۳) ساخت `shared/config.php`

### راهِ سریع: صفحه‌ی `setup.php`

1. `https://YOUR-SITE/setup.php` را باز کنید.
2. در بخش «۲) ساخت shared/config.php» اطلاعات را وارد کنید:
   - **هاست دیتابیس** (روی بیشتر هاست‌ها `localhost`)
   - **نام دیتابیس** و **نام کاربری** و **رمز** (از cPanel ← MySQL® Databases)
   - **پنل پیامک**: نام کاربری/رمز/شناسه‌ی متنِ Payamak (یا توکن AmootSMS)
   - منطقه‌ی زمانی: `Asia/Tehran` (پیش‌فرض درست است)
3. دکمه‌ی «آزمایش اتصال و ذخیره‌ی تنظیمات» را بزنید. اتصال **پیش از نوشتن** آزمایش
   می‌شود، پس تنظیمِ خراب ذخیره نمی‌شود و خطای واقعی را همان‌جا می‌بینید.

### راهِ دستی (FTP / File Manager)

از روی الگو یک کپی بسازید و مقادیر را پر کنید:

```bash
cp shared/config.example.php shared/config.php
chmod 600 shared/config.php
```

```php
return [
    'driver' => 'mysql',
    'host'   => 'localhost',
    'user'   => 'USER_DBUSER',
    'pass'   => 'PASSWORD',
    'name'   => 'USER_DBNAME',

    'db_timezone'      => 'Asia/Tehran',
    'display_timezone' => 'Asia/Tehran',

    /* پنل پیامک — بدون این‌ها «کد تایید» ارسال نمی‌شود */
    'payamak_username'    => 'YOUR_PAYAMAK_USERNAME',
    'payamak_password'    => 'YOUR_PAYAMAK_PASSWORD',
    'payamak_template_id' => '12345',   /* شناسه‌ی «متن تأییدشده» (bodyId) — فقط رقم */
    /* یا به‌جای Payamak:  'amootsms_token' => 'YOUR_TOKEN', */

    'otp_test_code' => '',              /* در تولید حتماً خالی */
];
```

## ۴) دیتابیس

1. در cPanel یک دیتابیس **خالی** بسازید و یک کاربر با دسترسی کامل روی آن
   (`ALL PRIVILEGES`) تعریف کنید.
2. **ساختار جدول‌ها خودکار است**: به‌محض برقراری اتصال، کد پروژه جدول‌ها و کاربر
   پیش‌فرض ادمین (`admin` / `admin123`) را می‌سازد و ستون‌های تازه را اضافه می‌کند.
   (در `setup.php` دکمه‌ی «ساخت/ترمیم جدول‌ها» همین کار را دستی انجام می‌دهد.)
3. اگر می‌خواهید **داده‌های قبلی** (گزارش‌ها/کاربران/اخبار) برگردد: فایل SQL را در
   **phpMyAdmin ← Import** اجرا کنید (فایل‌های dump داخل بسته‌ی آپلود نیستند؛
   از مخزن/پشتیبان خودتان بردارید: `backend/eplak-db.sql`).
4. اگر کاربر دیتابیس اجازه‌ی `ALTER` ندارد (بعضی هاست‌های قفل‌شده)، در `config.php`
   `'schema_alter' => false` بگذارید؛ کد در «حالت سازگار» کار می‌کند.
5. برای تعمیرهای موردی هم این دو فایل داخل بسته هستند (در phpMyAdmin اجرا کنید):
   `backend/fix-notifications-db.sql` و `backend/fix-news-db.sql`.

## ۵) اجازه‌ی نوشتن پوشه‌ها

| پوشه | برای چه | اجازه |
|---|---|---|
| `uploads/` | عکس/فیلم گزارش‌ها و تصویر اخبار | `755` (یا `775`) — نوشتنی توسط PHP |
| `data/` | فایل دیتابیس SQLite (فقط حالت آزمایش) | نوشتنی |
| `shared/` | ساخت `config.php` با `setup.php` | نوشتنی تا پایان راه‌اندازی |

در `setup.php` وضعیت نوشتنی بودن هر سه پوشه نشان داده می‌شود.

## ۶) ساعت و تاریخ (تهران/شمسی)

`'db_timezone' => 'Asia/Tehran'` و `'display_timezone' => 'Asia/Tehran'` بگذارید.
اگر دیتابیس قدیمی‌تان با ساعت UTC پر شده و نمی‌خواهید نشست عوض شود،
`'db_timezone' => 'UTC'` بگذارید (نمایش همچنان تهران می‌شود).
جزئیات: `docs/JALALI_FA.md`.

## ۷) اعلان روی اپ اندروید (APK)

برای رسیدن اعلان وقتی اپ بسته است، **کلید سرویس فایربیس** لازم است:

1. `console.firebase.google.com` ← پروژه‌ی `eplak-63c74`
2. **Project settings ← Service accounts ← Generate new private key** ⇒ دانلود JSON
3. پنل ← **تنظیمات ← «اعلان گوشی برای اپ اندروید (فایربیس)»** ⇒ چسباندن محتوای
   کامل فایل ⇒ ذخیره ⇒ «عیب‌یابی» و «ارسال اعلان آزمایشی»

اگر این کلید نباشد، صفحه‌ی «اعلان‌ها» در پنل **بنر قرمز** نشان می‌دهد.
جزئیات: `docs/NOTIFICATIONS_FA.md` و `docs/FIREBASE_SETUP_FA.md`.

## ۸) اگر دامنه یا پوشه عوض شده (اپ موبایل)

اپ اندروید/iOS با `file://` اجرا می‌شود، پس آدرس API را از
`core/storage.js` می‌گیرد:

```js
const BACKEND_BASE_URL = window.EPLAK_API_BASE_URL ||
  (window.location.protocol === 'file:' ? 'https://eplak.ir/eplak-fixed/api' : 'api');
```

- **نسخه‌ی وب/PWA**: آدرس نسبی (`api`) است ⇒ با هر دامنه/پوشه‌ای خودکار کار می‌کند.
- **APK/IPA**: اگر دامنه یا پوشه عوض شده، باید این آدرس به نشانی تازه تغییر کند و
  اپ **دوباره ساخته و نصب** شود (GitHub Actions ← ورک‌فلوی «ساخت اپ اندروید» /
  «ساخت اپ iOS»). تا نصب نسخه‌ی تازه، اپِ قدیمی به هاست قبلی درخواست می‌زند.

- [ ] تاریخ‌ها شمسی و ساعت تهران است

## ۱۱) نکته‌ی امنیتی

- `setup.php` فقط وقتی اجازه‌ی نوشتن دارد که `shared/config.php` **وجود نداشته باشد**
  (اجرای اول) یا **مدیر وارد پنل شده باشد**؛ بعد از آن فرم فقط‌خواندنی است و
  هیچ رمزی در خروجی چاپ نمی‌شود. همه‌ی کنش‌های POST با توکن CSRF نشست بررسی می‌شوند.
- پس از راه‌اندازی، `setup.php` را حذف کنید (دکمه‌ی «حذف setup.php» با ورود مدیر،
  یا پاک کردن دستی از FTP).
- فایل‌های فقط-توسعه (`router_admin.php` و `preview-hub.html`) از مخزن حذف شده‌اند و
  در `.htaccess` هم بسته شده‌اند؛ اگر نسخه‌ی قدیمی‌شان روی هاست مانده، از وب
  دسترسی نخواهند داشت (بهتر است دستی هم پاکشان کنید).
