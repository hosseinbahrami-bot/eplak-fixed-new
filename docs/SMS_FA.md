# راهنمای پیامک (ملی پیامک) — کد تایید ورود

> همه‌ی چیزی که برای راه‌اندازی، عیب‌یابی و آزمایشِ «کد تایید پیامکی» لازم است.
> نسخه‌ی کوتاهِ راه‌اندازی روی هاست تازه: [`docs/NEW_HOST_FA.md`](NEW_HOST_FA.md).

## ۱) پیامک در این پروژه کجا استفاده می‌شود؟

تنها در **یک** جا: «کد تایید» چهاررقمیِ ورود به اپ (و پنل). کاربر شماره‌ی
موبایلش را وارد می‌کند، سرور یک کد چهاررقمی می‌سازد، با **الگوی تأییدشده**
(پترن) ملی پیامک برایش می‌فرستد، و فقط «هشِ» کد در دیتابیس ذخیره می‌شود
(`otp_challenges.code_hash`) — یعنی حتی اگر دیتابیس لو برود، کدِ کسی قابلِ
خواندن نیست.

**تنها ارائه‌دهنده‌ی پیامکِ پروژه «ملی پیامک» است** (`rest.payamak-panel.com`).
آموت‌اس‌ام‌اس به درخواست کارفرما کاملاً حذف شده است؛ پس هیچ مسیرِ دومی وجود
ندارد که عیب‌یابی را پیچیده کند.

| چیز | کجا |
| --- | --- |
| نشانیِ سرویسِ ارسال | `EPLAK_PAYAMAK_ENDPOINT` در `shared/payamak.php` |
| تابعِ ارسال (تنها تابعِ ارسالِ پروژه) | `eplakPayamakSendCode()` در `shared/payamak.php` |
| ترجمه‌ی فارسیِ کدهای پاسخ | `eplakPayamakStatusText()` و `eplakPayamakExplain()` |
| فرستنده‌ی «کد تایید» | `api/auth.php` (اکشن `send`) |
| «ارسال پیامک آزمایشی» | پنل → **تنظیمات** → بخش «پیامکِ کد تایید» (`admin/settings.php`) |
| راه‌انداز (وارد کردن کلیدها) | `setup.php` در ریشه‌ی سایت |
| نقطه‌ی تشخیصِ سلامت | `https://…/api/status.php` → بخش `sms` |

## ۲) تنظیمات (`shared/config.php`)

```php
return [
    /* … دیتابیس … */

    /* پنل ملی پیامک */
    'payamak_username'    => '19350505507',   // نام کاربری پنل
    'payamak_api_key'     => 'کلیدِ API',      // ← مهم‌ترین قلم (پایین توضیح داده شده)
    'payamak_password'    => '',              // قدیمی/سازگاری — خالی بگذارید
    'payamak_template_id' => '573639',        // شناسه‌ی «متن تأییدشده» (bodyId)
];
```

متغیرهای محیطیِ معادل (اگر نمی‌خواهید مقدارها داخل فایل باشند) و **ترتیبِ
خواندن** — یک‌جا در `shared/payamak.php` پیاده شده و همه‌ی مصرف‌کننده‌ها
(`api/auth.php`، `api/status.php`، `setup.php`، پنل) دقیقاً همین ترتیب را
دارند:

```
PAYAMAK_API_KEY  ←  payamak_api_key  ←  PAYAMAK_PASSWORD  ←  payamak_password
```

یعنی اگر قبلاً کلید را در `payamak_password` گذاشته‌اید، **بدونِ هیچ تغییری
کار می‌کند**؛ فقط نامِ جایش دقیق نبوده است.

### ⭐ مهم‌ترین نکته: «کلید API» نه «رمز عبورِ پنل»

وب‌سرویسِ ملی پیامک یک فیلد به نام `password` دارد، ولی مقدارِ درستِ آن
**«کلید API» (ApiKey)** است — نه رمزِ عبوری که با آن وارد پنل می‌شوید. اگر
رمزِ عبورِ پنل فرستاده شود، پاسخ این است:

```json
{"RetStatus":"-110","StrRetStatus":"الزام استفاده از ApiKey به جای رمز عبور","Value":"-110"}
```

و در اپ فقط «ارسال کد تایید انجام نشد» دیده می‌شود.

**کلید API از کجا؟** پنل ملی پیامک ← **توسعه‌دهندگان** ← **تنظیمات وب‌سرویس**
← **API Key** (دیدن/کپی/ساختِ کلیدِ تازه). این کار رایگان است.

دو نکته‌ی عملی:

1. اگر «رمز عبورِ پنل» را عوض کنید، کلیدِ APIِ قبلی **باطل** می‌شود ⇒ دوباره
   از پنل کپی کنید.
2. اگر در پنل «محدودسازی IP» روشن باشد، IP سرورِ هاست باید در فهرستِ
   **IPهای مجاز** باشد؛ وگرنه پاسخ `-109`/`-111` می‌آید (کلید درست است، ولی
   IP پذیرفته نمی‌شود).

## ۳) جدولِ کدهای پاسخ (ترجمه‌ی فارسیِ خودکار)

از نسخه‌ی فعلی، هر کدِ پاسخ **فارسی ترجمه می‌شود** و در سه جا دیده می‌شود:
پیامِ کاربر در اپ، صفحه‌ی «پیامکِ آزمایشی» در پنل، و `error_log` هاست.

| کد | معنی | چه‌کار باید کرد |
| --- | --- | --- |
| `1` | موفق — پیامک به صفِ ارسال رفت (`Value` = شناسه‌ی رکورد) | — |
| `0` | نام کاربری یا کلید API اشتباه است | کلید را دوباره از پنل کپی کنید |
| `-110` | **باید به‌جای رمز عبور، کلید API فرستاده شود** | `payamak_api_key` را پر کنید |
| `-109` | محدودسازی IP فعال است و IP سرور مجاز نیست | در پنل: تنظیمات وب‌سرویس ← IPهای مجاز |
| `-111` | IP نامعتبر | همان `-109` |
| `-108` | IP مسدود شده | پشتیبانی ملی پیامک |
| `-4` | شناسه‌ی متن (`bodyId`) اشتباه یا تأییدنشده | الگو را در پنل «تأییدشده» کنید یا `payamak_template_id` را درست بگذارید (پیش‌فرضِ پروژه `573639`) |
| `-5` | متن با متغیرهای الگو مطابقت ندارد | الگو باید دقیقاً یک متغیرِ عددی (کد) داشته باشد |
| `-1` | وب‌سرویسِ الگو (pattern) غیرفعال است | در پنل فعالش کنید |
| `-10` | ارتباطی بین متن و متغیرها نیست | متنِ الگو را بررسی کنید |
| `-3` / `-7` | خطِ ارسال‌کننده تعریف نشده / نامعتبر | در پنل یک خطِ تأییدشده انتخاب کنید |
| `2` | اعتبارِ پنل کافی نیست | پنل را شارژ کنید |
| `35` | شماره‌ی گیرنده در لیست سیاه مخابرات است | با شماره‌ی دیگری امتحان کنید |
| `7` | شماره/کلمه فیلتر شده | همان `35` |
| `19` | سقفِ ارسالِ ساعتی پر شده | کمی بعد دوباره |
| `-8` | خارج از بازه‌ی مجازِ ۰۷:۰۰ تا ۲۲:۰۰ | در همان بازه آزمایش کنید |
| `-9` | زمانِ درخواست در گذشته است | ساعتِ سرور را بررسی کنید (پروژه روی `Asia/Tehran` است) |
| `-6` / `6` | سامانه در حال به‌روزرسانی است | چند دقیقه بعد |
| `10` | کاربرِ پنل غیرفعال است | پشتیبانی ملی پیامک |
| `11` | ارسال نشد (خطای عمومیِ پنل) | دوباره؛ اگر ماند، پشتیبانی |
| `12` | مدارکِ پنل ناقص / خط فعال نشده | مدارک را در پنل کامل کنید |
| `-2` | در هر درخواست فقط یک شماره مجاز است | کدِ پروژه همیشه یک شماره می‌فرستد |

اگر کدِ ناشناخته‌ای برگردد، همان `StrRetStatus`ِ سرویس به کاربر نشان داده
می‌شود و در گزارش هم می‌آید (هیچ «ترجمه‌ی ساختگی» نوشته نمی‌شود).

## ۴) «ارسال پیامک آزمایشی» در پنل

**پنل → تنظیمات → بخش «پیامکِ کد تایید» (ملی پیامک)** — فقط **مدیرِ کل**
(نقش `super_admin`) این صفحه را می‌بیند؛ مدیرِ حوزه/معاونت با `403` رد
می‌شود و فرم هم توکنِ CSRF دارد، پس از بیرونِ پنل قابلِ صدا زدن نیست.

چه چیزی نشان داده می‌شود؟

- **آماده‌ی ارسال؟** — نام کاربری + کلید + شناسه‌ی رقمیِ متن
- **کلیدِ دسترسی** — «کلید API (درست)» یا «از `payamak_password` خوانده
  می‌شود (قدیمی)» یا «تنظیم نشده». **مقدارِ کلید هرگز نمایش داده نمی‌شود.**
- **شناسه‌ی متن (bodyId)** مؤثر + اینکه پیش‌فرضِ پروژه است یا خودتان وارد
  کرده‌اید
- **ماژول cURL** سرور و نشانیِ سرویس

دکمه‌ی **«ارسال پیامک آزمایشی»** یک شماره می‌گیرد و **دقیقاً همان مسیری** را
می‌رود که «کد تایید» واقعی می‌رود (`eplakPayamakSendCode`) — یعنی نتیجه‌اش
واقعاً نشان می‌دهد کلید و الگو درست است یا نه، نه یک بررسیِ سطحی. بعد از
ارسال، `RetStatus` و `StrRetStatus`، **ترجمه‌ی فارسی**، «چه‌کار باید کرد»،
شناسه‌ی رکوردِ ارسال و کدِ HTTP نمایش داده می‌شود.

محدودیت‌ها: بین دو آزمایش **۳۰ ثانیه** فاصله لازم است (تا اعتبارِ پیامکِ سایت
هدر نرود) و اگر تنظیمات آماده نباشد دکمه **غیرفعال** است.

> پیامکِ آزمایشی یک پیامکِ **واقعی** است و از اعتبارِ پنل کم می‌کند.

## ۵) گزارش‌ها (`error_log` هاست)

هر ارسال — موفق یا ناموفق — **یک خط** گزارش می‌گیرد:

```
[eplak-otp] [eplak-sms] http=200 ret=-110 str=الزام استفاده از ApiKey به جای رمز عبور value=-110 fa=باید به‌جای «رمز عبور پنل»، «کلید API» فرستاده شود to=0912***567 bodyId=573639 secret=password result=rejected
```

- `to=` **پوشیده** است (`0912***567`) — شماره‌ی شهروند داده‌ی شخصی است.
- `secret=` فقط **منبعِ** کلید است (`api_key` یا `password`)، نه خودِ کلید.
- **هیچ کلید، رمز یا متنِ پیامکی در گزارش نمی‌آید.**
- برچسب‌ها: `[eplak-otp]` (مسیرِ ورودِ کاربر)، `[eplak-sms]` (خودِ ارسال)،
  `[eplak-sms-test]` (پیامکِ آزمایشیِ پنل)، `[eplak-setup]` (راه‌انداز).

## ۶) پوشه‌های نوشتنی و `setup.php`

«کد تایید نمی‌آید» گاهی از پیامک نیست: اگر `shared/config.php` نباشد، سایت
اصلاً به دیتابیس نمی‌رسد. برای همین `setup.php`:

- برچسبِ **درستِ** فیلد را نشان می‌دهد: «ملی پیامک — **کلید API** (به‌جای
  رمز عبورِ پنل)» و دلیلِ خطای `-110` را توضیح می‌دهد.
- تنظیمِ **نیمه** (فقط نام کاربری، بدون کلید) را **ذخیره نمی‌کند** — چون از
  تنظیم‌نشده بدتر است.
- وضعیتِ پوشه‌ها را **صادقانه** می‌گوید: `shared`, `data`, `uploads`,
  `uploads/reports`, `uploads/news`, `uploads/ads`, `uploads/tmp` — هرکدام
  «هست و نوشتنی است» / «هست ولی نوشتنی نیست» / «اصلاً وجود ندارد».
- دکمه‌ی **«ساخت پوشه‌های نوشتنی»** همان پوشه‌ها را با اجازه‌ی `775` می‌سازد
  و نگهبانِ `uploads/.htaccess` (جلوگیری از اجرای اسکریپت در پوشه‌ی آپلود) را
  می‌نویسد. اگر PHP اجازه‌ی ساخت نداشته باشد، **صادقانه** می‌گوید کدام پوشه
  نوشتنی نشد و راهِ دستی (cPanel ← File Manager ← `chmod 775`) را نشان می‌دهد.

بسته‌ی آپلودِ هاست (`eplak-fixed-update.zip`) این پوشه‌ها را **خالی** با خودش
می‌برد (با یک فایلِ نشانه و `uploads/.htaccess`) تا بعد از Extract آپلودِ عکسِ
گزارش از کار نیفتد — ولی نه عکس/فیلمِ کاربران و نه دیتابیس را.

## ۷) عیب‌یابیِ سریع

| علامت | دلیلِ رایج | راه‌حل |
| --- | --- | --- |
| «پنل ملی پیامک تنظیم نشده است…» | `payamak_username` یا کلید خالی است | `setup.php` یا `shared/config.php` |
| «تنظیمات پنل ملی پیامک کامل نیست» | فقط یکی از دو قلم وارد شده | هر دو (یا هیچ‌کدام) |
| «کلیدِ دسترسیِ پنل پیامک پذیرفته نشد» | `-110` یا `0` | کلید APIِ درست از پنل |
| «سامانه‌ی پیامک، IP سرور را نپذیرفت» | `-109`/`-111`/`-108` | IP سرور را در پنل مجاز کنید |
| «الگوی پیامک … تأیید نشده است» | `-4`/`-5`/`-1` | الگوی تأییدشده یا `payamak_template_id` درست |
| «اعتبارِ پنلِ پیامک تمام شده است» | `2` | شارژ پنل |
| «برای این شماره امکانِ دریافت پیامک وجود ندارد» | `35`/`7` | لیست سیاه مخابرات |
| «ارسال پیامک در این ساعت مجاز نیست» | `-8` | بازه‌ی ۰۷:۰۰ تا ۲۲:۰۰ |
| «اتصال سرور به سامانه‌ی پیامک برقرار نشد» | cURL/خروجیِ هاست بسته است | `api/status.php` و `error_log` را ببینید |
| کد می‌آید ولی در اپ قبول نمی‌شود | ساعتِ سرور یا انقضای ۵ دقیقه‌ای | منطقه‌ی زمانی `Asia/Tehran`؛ `api/status.php` |

همیشه اول `api/status.php` را باز کنید: بخش `sms` می‌گوید آماده هست یا نه، کلید
از کدام تنظیم خوانده شده، شناسه‌ی متن مؤثر چیست، و بخش `problems` هم
«چه‌کار باید کرد» را به فارسی می‌نویسد.

## ۸) آزمون‌های خودکار

`bash tools/dev/run-regression.sh sms` (و `otp`) این‌ها را **با اجرای واقعیِ
PHP** بررسی می‌کنند: ترتیبِ خواندنِ کلیدها، ترجمه‌ی همه‌ی کدهای جدول بالا،
نبودِ کلید در `error_log`، محافظ‌های پیش از ارسال (شماره‌ی نامعتبر/نبودِ
کلید/شناسه‌ی غیررقمی ⇒ هیچ درخواستِ شبکه‌ای نمی‌رود)، برچسبِ «کلید API» و
نوشتنِ `payamak_api_key` در `setup.php`، «ساخت پوشه‌های نوشتنی» + نگهبانِ
`uploads/.htaccess`، `403` بودنِ پیامکِ آزمایشی برای مدیرِ حوزه/معاونت، و
هدرهای CORS روی مسیرِ خطای دیتابیس.
