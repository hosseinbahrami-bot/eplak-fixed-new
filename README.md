## 🔔 اعلان‌ها

| حالت | وضعیت |
|---|---|
| داخل اپ (فهرست اعلان‌ها) | ✅ کار می‌کند — با هر ثبت درخواست، پیام «درخواست شما با کد پیگیری … در تاریخ … ثبت شد» همان لحظه ساخته می‌شود |
| اعلان ارسالی از پنل ادمین | ✅ هم برای یک شماره و هم «برای همه»؛ روی دیتابیس قدیمی هم (بدون ستون `send_id`) کار می‌کند |
| نوار اعلان گوشی، وقتی اپ باز است | ✅ نمایش داده می‌شود (اجازه‌ی اعلان باید داده شده باشد) |
| نوار اعلان گوشی، وقتی اپ بسته است | ⏳ با فایربیس (FCM) فرستاده می‌شود؛ برای رسیدن قطعی، کلید سرویس فایربیس باید در پنل → تنظیمات وارد شده باشد (`docs/FIREBASE_SETUP_FA.md`) — تا تأیید روی گوشی کاربر، ادعای «فعال بودن کامل» مطرح نمی‌شود |
| حذف اعلان | ✅ دکمه‌ی سطل‌زباله روی هر اعلان + «حذف همه» در سرصفحه (فقط از فهرست همان کاربر) |

> 🩺 **اگر اعلان‌ها در اپ نمی‌آیند** (یا پنل ادمین «⚠️ خطا در ارسال» می‌دهد): علتش معمولاً
> «قدیمی بودن ساختار جدول اعلان‌ها» در دیتابیس هاست است — ستون `send_id` نیست، کلید خارجی
> `user_phone → users(phone)` هست و نویسه‌گان جدول `utf8` سه‌بایتی است (ایموجی ذخیره نمی‌شود).
> کدِ فعلی هر سه را **خودکار** ترمیم می‌کند و اگر کاربر دیتابیس اجازه‌ی `ALTER` نداشته باشد هم
> اعلان‌ها در «حالت سازگار» ذخیره و نمایش داده می‌شوند. برای ترمیم قطعی و یک‌جا، این فایل را
> یک‌بار در phpMyAdmin اجرا کنید: [`backend/fix-notifications-db.sql`](backend/fix-notifications-db.sql)
> (و در پنل → تنظیمات → «ترمیم ساختار دیتابیس»). جزئیات: `docs/NOTIFICATIONS_FA.md`

> 📌 برای اعلان روی گوشی: در تنظیمات گوشی → برنامه‌ها → ای‌پلاک → اعلان‌ها، اجازه‌ی اعلان را روشن کنید
> و آخرین نسخه‌ی اپ را از بخش [Releases](https://github.com/hosseinbahrami-bot/eplak-fixed-new/releases) نصب کنید.

### 📰 اخبار و دانستنی‌ها (بخش «اخبار و اطلاعیه‌ها» در اپ)

| حالت | وضعیت |
|---|---|
| فهرست خبرها و اطلاعیه‌ها در اپ | ✅ از سرور خوانده می‌شود؛ اگر سرور فهرست خالی بدهد «کارت راهنما» نشان داده می‌شود (نه صفحه‌ی سفید، نه محتوای بیات) |
| کارت‌های «دانستنی‌های ورامین» و نوار «آخرین اخبار» در خانه | ✅ با عکس و نشان (badge) مطلب |
| عکسِ آپلودشده از پنل | ✅ در اپ هم دیده می‌شود (نشانی مطلق سرور؛ `assets/…` آفلاین می‌ماند) |
| افزودن/ویرایش/حذف از پنل ادمین | ✅ با عکس (آپلود از سیستم یا نشانی دستی)، خلاصه، متن کامل، آیکون، نشان، ترتیب و وضعیت انتشار |
| دیتابیس قدیمی هاست | ✅ اگر جدول `news` نیست ساخته می‌شود؛ اگر ستون `badge` نیست یا نویسه‌گان `utf8` است، کد در «حالت سازگار» کار می‌کند و دقیقاً می‌گوید چه چیزی ذخیره نشد |

> 🩺 **اگر «اخبار و اطلاعیه‌ها» خالی است**: علتش ساختار قدیمیِ جدول `news` در دیتابیس هاست است
> (در دامپ اصلی جدول `news` وجود ندارد و در دامپ قدیمی ستون `badge` نیست و نویسه‌گان `utf8`
> سه‌بایتی ایموجی را ذخیره نمی‌کند). کدِ فعلی هر سه را **خودکار** ترمیم می‌کند:
> پنل ادمین → تنظیمات → «ترمیم ساختار دیتابیس»، یا پنل → اخبار و دانستنی‌ها →
> «تعمیر خودکار جدول اخبار». اگر کاربر دیتابیس اجازه‌ی `CREATE`/`ALTER` ندارد، یک‌بار
> [`backend/fix-news-db.sql`](backend/fix-news-db.sql) را در phpMyAdmin اجرا کنید.
> جزئیات کامل (ریشه‌ها، توابع، آزمون ۷۴ بررسی‌ای): `docs/NEWS_FA.md`

### 🗓️ تاریخ‌ها شمسی است (هم اپ، هم پنل ادمین)

| جای نمایش | پیش از این | حالا |
|---|---|---|
| اپ: تاریخ درخواست ثبت‌شده، فهرست «درخواست‌های من»، جزئیات و روند رسیدگی | `2026-10-11 13:24:05` (میلادیِ خام) | `۱۴۰۵/۰۷/۱۹ - ساعت ۱۶:۵۴` |
| اپ: تاریخ خبرها، دانستنی‌ها و اعلان‌ها | روی iOS/بعضی WebViewها میلادی با رقم فارسی | شمسی (بدون وابستگی به `Intl` مرورگر) |
| پنل ادمین: گزارش‌ها، تیکت‌ها، کاربران، اخبار، اعلان‌ها، تنظیمات، لاگ ارسال | `۲۰۲۶-۱۰-۱۱ ۱۳:۲۴:۰۵` (فقط رقم‌ها فارسی بود) | `۱۴۰۵/۰۷/۱۹ - ساعت ۱۶:۵۴` |
| حالت انگلیسیِ اپ | — | میلادیِ خوانا (`2026-10-11 16:54`) — کاربر انگلیسی‌زبان شمسی نمی‌خواهد |

هر دو سمت از **یک الگوریتم** استفاده می‌کنند (`shared/fa_datetime.php` در سرور و
`core/state.js` در اپ) تا تاریخِ یک رویداد در اپ و پنل مو‌به‌مو یکی باشد.
ساعتِ دیتابیس به‌صورت پیش‌فرض `UTC` فرض می‌شود و به **وقت تهران** نمایش داده می‌شود؛
اگر ساعت دیتابیس هاست شما تهران است، در `shared/config.php` بگذارید:
`'db_timezone' => 'Asia/Tehran'` (یا متغیر محیطی `EPLAK_DB_TIMEZONE=Asia/Tehran`) تا
زمان‌ها ۳:۳۰ ساعت جابه‌جا نشوند. جزئیات و آزمون‌ها: `docs/JALALI_FA.md`

## 🧪 آزمون‌های خودکار

```bash
bash tools/dev/run-regression.sh          # همه‌ی آزمون‌های خودکار
bash tools/dev/run-regression.sh fcm      # فقط موتور فایربیس
bash tools/dev/run-regression.sh syntax   # فقط بررسی نحوی PHP و JS
bash tools/dev/run-regression.sh places   # نقشه و اماکن شهری + مسیریابی با نشان
bash tools/dev/run-regression.sh placesadmin   # مدیریت اماکن از پنل ادمین (PHP واقعی)
bash tools/dev/run-regression.sh security   # ابزار ناامن rescue-db.php حذف شده و برنمی‌گردد
bash tools/dev/run-regression.sh ios        # پروژه‌ی iOS، بسته‌ی وب، پل GPS، ورک‌فلوها
bash tools/dev/run-regression.sh pwa        # manifest، ساخت نسخه‌ی ایستای PWA
```

همین آزمون‌ها با هر تغییر روی گیت‌هاب هم اجرا می‌شوند:
**Actions → «آزمون‌های خودکار (Regression)»**.

## 🤖 ساخت خودکار APK

با هر تغییر در فایل‌های اپ/سایت، گیت‌هاب خودش APK تازه می‌سازد و در Releases می‌گذارد:
**Actions → Build Android APK**. کلید امضای اپ ثابت می‌ماند تا نسخه‌ی تازه روی نسخه‌ی نصب‌شده به‌روزرسانی شود.

## 🍎 ساخت خودکار اپ iOS و PWA

با هر تغییر در فایل‌های اپ/سایت، گیت‌هاب علاوه بر APK این‌ها را هم می‌سازد و به همان صفحه‌ی Releases می‌گذارد:

- **Actions → Build iOS IPA** (روی macOS): اپ را روی شبیه‌ساز iPhone واقعاً اجرا و می‌سنجد (پینگ سرور، نقشه، «موقعیت من»، لینک نشان)،
  سپس `eplak-app-unsigned.ipa` (بدون امضا) و `eplak-ios-project.zip` (پروژه‌ی Xcode) را می‌سازد.
- **Actions → Build PWA package**: PWA را در Chrome واقعی، روی origin جدا و با سرور واقعی می‌سنجد (CORS، سرویس‌ورکر، قابلیت نصب، نقشه)
  و روی **GitHub Pages** منتشر می‌کند (`https://hosseinbahrami-bot.github.io/eplak-fixed/`؛ مالک مخزن یک‌بار: Settings ← Pages ← Source: GitHub Actions).
