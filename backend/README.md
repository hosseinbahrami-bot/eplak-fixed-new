# پوشه‌ی `backend/` — فایل‌های SQL دیتابیس

بک‌اندِ واقعی ای‌پلاک **PHP** است و در ریشه‌ی مخزن قرار دارد
(`api/` برای اپ، `admin/` برای پنل مدیریت، `shared/` برای منطق مشترک).
این پوشه فقط **فایل‌های SQL** دیتابیس را نگه می‌دارد.

> پیش از این یک `package.json` مربوط به یک بک‌اند Node/Express قدیمی
> (`server.js`) هم این‌جا بود که سال‌ها استفاده نمی‌شد و فایلی به آن نام در مخزن
> وجود نداشت؛ حذف شد تا ساختار پروژه گمراه‌کننده نباشد.

| فایل | چیست | کجا استفاده می‌شود |
|---|---|---|
| `eplak-db.sql` | دامپِ کامل دیتابیس (ساختار + داده‌های شهروندان) | بازیابی داده‌های قدیمی روی هاست تازه با **phpMyAdmin ← Import** |
| `DBasli/` | دامپِ اصلی/اولیه‌ی دیتابیس | مرجعِ بازیابی |
| `fix-notifications-db.sql` | ترمیم جدول اعلان‌ها روی دیتابیس قدیمی (ستون `send_id`، کلید خارجی `user_phone`، نویسه‌گان `utf8mb4`) | وقتی کاربر دیتابیس اجازه‌ی `CREATE/ALTER` ندارد؛ پنل هم به همین مسیر اشاره می‌کند |
| `fix-news-db.sql` | ساخت/ترمیم جدول اخبار (`news`) روی دیتابیس قدیمی | وقتی بخش «اخبار و دانستنی‌ها» خالی است |

## نکات مهم

- **ساختار جدول‌ها خودکار است**: به‌محض برقراری اتصال، `shared/bootstrap.php`
  جدول‌ها و کاربر پیش‌فرض ادمین (`admin` / `admin123`) را می‌سازد و ستون‌های
  تازه را اضافه می‌کند. یعنی روی هاست تازه **لازم نیست** این فایل‌ها را اجرا کنید؛
  فقط `shared/config.php` را بسازید (راه سریع: صفحه‌ی `setup.php` در ریشه‌ی سایت).
- **داده‌ی شخصی شهروندان** داخل `eplak-db.sql` و `DBasli/` است (به خواسته‌ی مالک
  پروژه نگه داشته شده‌اند). به همین دلیل:
  - این پوشه **داخل بسته‌ی آپلود هاست نمی‌رود**
    (`tools/build-update-package.sh` فقط دو فایل کوچک `fix-*.sql` را اضافه می‌کند)
  - و در ورک‌فلوی FTP هم پیش از آپلود پاک می‌شود.
- برای راه‌اندازی روی هاست تازه، راهنمای گام‌به‌گام: `docs/NEW_HOST_FA.md`.
